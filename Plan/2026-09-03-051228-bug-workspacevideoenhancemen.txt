  - File: /workspace/Video_Enhancement/external/ifrnet_video/main.py
  - Issue: _reuse_env = os.environ.get('IFRNET_NVENC_CROSS_SEGMENT_REUSE', '1')
    defaults to '1' (enabled), but the comment explicitly states "HEVC/AV1
    默认禁止跨段复用编码器" (HEVC/AV1 defaults to DISABLE cross-segment encoder
    reuse)
  - Impact: Causes "PPS id out of range" and "Could not find ref with POC"
    errors in logs 1 & 2 (segments 2 and 5 fail decoding validation)

  Bug 2: Missing cuDevicePrimaryCtxRelease in close()

  - File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py
  - Issue: _acquire_cuda_context() calls cuDevicePrimaryCtxRetain() but close()
    never calls cuDevicePrimaryCtxRelease()
  - Impact: Primary context retain count leaks across encoder recreations,
    eventually causing resource exhaustion and segfaults

  Bug 3: CUDA Context Stack Corruption in close()

  - File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py (line
    ~3150-3157)
  - Issue: close() directly calls cuCtxPushCurrent(self._saved_ctx) without
    first popping the current context (which may be the primary context from the
    last encode operation)
  - Impact: Unbalanced context stack leads to segfault on next encoder creation
    (logs 3 & 4 crash at segment 2)

  Bug 4: SPS/PPS Cache Not Cleared on Encoder Reuse for New Segment

  - File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py (line
    ~1905-1909)
  - Issue: _stream_begin() resets _sps_pps_injected = False but _cached_sps_pps
    persists across segments. When reusing encoder, old SPS/PPS may be prepended
    to new segment's frames.
  - Impact: "PPS id out of range" errors in logs 1 & 2

  Bug 5: _frame_idx Not Reset on New Encoder Creation (Minor)

  - File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py (line
    ~592)
  - Issue: When new encoder is created (non-reuse path), _frame_idx = 0 is set
    in __init__, but if somehow a stale encoder is used, frame indexing could be
    wrong

  ---

  Proposed Fixes

  1. Fix Line 1101: Change default from '1' to '0' to match documented behavior
  2. Add cuDevicePrimaryCtxRelease in close() after destroying encoder
  3. Fix context restoration in close(): Pop current context before pushing
     saved context
  4. Clear _cached_sps_pps in _stream_begin() when force=True (new segment)
  5. Add defensive checks in _ctx_push to handle None primary context

     Root Cause Analysis

     Bug A: Missing cuDevicePrimaryCtxRelease in NVENCEncoder.close()

     File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py
     (~line 3116)
     - _acquire_cuda_context() calls cuDevicePrimaryCtxRetain() to get primary
       context
     - close() destroys encoder but never releases the retained primary context
     - Each segment creates new encoder → retains primary context → leak
       accumulates
     - Eventually causes resource exhaustion / segfault

     Bug B: CUDA Context Stack Corruption in close()

     File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py
     (~lines 3150-3157)
     # Current broken code:
     if self._saved_ctx.value is not None:
         self._libcuda.cuCtxPushCurrent(self._saved_ctx)  # WRONG: doesn't pop 
     current context first!
     - The current context at close() time is the NVENC encoder's primary
       context (pushed during encoding)
     - Directly pushing _saved_ctx without popping creates unbalanced context
       stack
     - Next segment's _acquire_cuda_context() fails with code=201 (context
       mismatch) → segfault

     Bug C: SPS/PPS Cache Not Cleared on Segment Boundary (when reusing encoder)

     File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py
     (~line 1909)
     - _stream_begin(force=True) resets _sps_pps_injected = False but keeps 
       _cached_sps_pps
     - When encoder is reused across segments, old segment's SPS/PPS gets
       prepended to new segment's frames
     - Causes "PPS id out of range" and "Could not find ref with POC" decode
       errors (Logs 1&2)

     Bug D: Context Push Failure Not Handled

     File: /workspace/Video_Enhancement/external/ifrnet_video/nvenc_sdk.py
     (~line 1380-1390)
     - _ctx_push() returns False on failure but callers don't check return value
     - If context push fails, subsequent CUDA operations use wrong context →
       undefined behavior

     Fixes Required

     Fix 1: Add cuDevicePrimaryCtxRelease in close()

     After destroying encoder, release the primary context that was retained.

     Fix 2: Fix Context Restoration in close()

     # Correct sequence:
     if need_pop:  # pop current (encoder's) context first
         cuCtxPopCurrent()
     if self._saved_ctx.value is not None:
