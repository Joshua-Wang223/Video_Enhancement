# HEVC 生产路径完全根治执行方案 — `hevc_la_disable` 软退役，`hevc_nvenc + LA>0` 完整方案

> 版本：2026-08-28  
> 依据：`Plan/codex-session-01a0414c-d030-71d2-b061-ebc37ecdf63f.md` / `memory/hevc-la-drain-diagnosis.md` / `Plan/HEVC_LA_BUG_实施完成总结.txt`  
> 决策：`hevc_la_disable` **保留字段但默认关闭（软退役）** — 仅作应急 `WARN` 逃生门，不再自动将 `LA>0` 降为 `0`。HEVC 在 `VBR_HQ/QVBR + LA=8/16` 下直通 `encode_frames_stream` 的已验证路径（`FIX-HEVC-COUNTED/EOS/EOS-FLUSH`）。

## 一、目标与验收标准

* **目标**：`hevc_nvenc` 在 `VBR_HQ/QVBR + LA=8/16` 下与 `h264_nvenc` 同等可靠，多段复用无死锁。
* **硬性验收**（`tests/verify_segment_bitstream_v4.py` 4检查）：
  1. `nb_read_frames == nb_read_packets`（无静默丢帧）
  2. 段首单 `IDR`（首个 `IDR` 后 32 `NAL` 内 `IDR=0`，≥3 连 `IDR` 才判 `FAIL`）
  3. `frame_num` 单调不回退
  4. 无 `pts_anomaly` / 解码错误
  5. 色度 6ROI（四角+中心+全局，`median*1.6` 下限 6/12）坏帧簇 `0`
  6. `ffmpeg -v error -i out -f null -` 空输出
* **门禁**：`tests/verify_plan_implementation.py` 89项 `0 FAIL` 新增 `FIX-HEVC-LA-OPEN`；`tests/diagnose_hevc_la.py --skip-reproducers` 6变体全绿。
