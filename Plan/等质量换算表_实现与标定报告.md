## 1. 方法

### 1.1 两条口径

| | `SIZE_MAP`（等体积，原 `QUALITY_MAP`） | `QUALITY_MAP`（等质量，原 `QUALITY_MAP_QUALITY`） |
|---|---|---|
| 插值基准 | `log(文件字节数)` | **VMAF** |
| 目标 | 同文件大小 | 同画质 |
| 默认 | — | **`--quality-mode` 默认值** |

两张表并存；`set_quality_mode('size'|'quality')` 选择，未覆盖的编码器自动回退 `SIZE_MAP`。

### 1.2 指标「唯一来源」（不可混用）

| 指标 | 来源 | 门禁强度 |
|---|---|---|
| **VMAF** | libvmaf `pooled_metrics.vmaf.mean` | **唯一硬门禁**（`|ΔVMAF| ≤ 1.0`） |
| **PSNR-HVS** | libvmaf `feature=name=psnr_hvs` | soft（只 WARN） |
| PSNR | 独立 `psnr` 滤镜 `average:` | soft（只 WARN） |
| SSIM | 独立 `ssim` 滤镜 `All:` | 参考 |
| XPSNR | 独立 `xpsnr` 滤镜 | 参考 |

> PSNR/HVS 降为 soft 的理由：等质量表以 **VMAF** 定标，**同 VMAF 不蕴含同 PSNR**，
> 用紧 PSNR 判红属跨轴假阳性。

### 1.3 标定流程

```
0. 钉死主指标与各指标唯一来源；记录 ffmpeg 二进制指纹
1. 统一预处理 → 1280x720 / yuv420p / 10s（无缓存：先删后建 + md5 审计）
2. libx264 -preset medium 扫锚点 CRF（第二轮: 18/22/26/30/34）
3. 目标编码器扫 10 个参数点，**两端必须包住锚点 VMAF 区间**
4. 对 (param, VMAF) 先做保序回归 (PAVA) 再插值 → 每个锚点的等 VMAF 参数
5. 对 (x264_CRF, 目标参数) 拟合 → 等质量表（pooled 斜率 + 各素材截距中位数）
6. 残差 / ΔVMAF 诊断；留一交叉验证
```

### 1.4 配套参数锁定（标定与下发必须一致）

| 编码器 | 质量参数 | 锁定参数 |
|---|---|---|
| libx264 / libx265 | `-crf` | `-preset medium` |
| libvpx-vp9 | `-crf` | `-b:v 0 -deadline good -cpu-used 2` |
| libsvtav1 | `-crf` | `-preset 8` |
| libaom-av1 | `-crf` | `-b:v 0 -cpu-used 6` |
| librav1e | `-qp` | `-speed` **按档**（native / 10 各一行） |

### 1.5 ⚠ **铁律：`n_subsample` 必须为 1**

`libvmaf` 的 `n_subsample=N`（每 N 帧算一次并池化）**会偏置 VMAF，且偏置量随编码器而异**
（实测同文件 vp9 crf35 差 **1.9~3.0**）。等 VMAF 匹配是在**跨编码器**之间做反查，
编码器相关的偏置会把匹配点整体推偏 —— 第一轮标定即栽在这里（§4）。

* 本机实测单点测量成本：`n_subsample=1` ≈ **44.7 s**；`n_subsample=8` ≈ 7.7 s（慢 5.8×）。
* 脚本默认已改为 **1**；`--subsample N>1` 仅可用于**同编码器内做趋势判断**，
  **不可用于标定**。

### 3.2 留一交叉验证（LOO）—— ❌ 未达标

工具：`Accessory/probe/loo_equal_quality.py`（VE）/ `probe/loo_equal_quality.py`（VU）。
标定 harness **不再内置 `--loo`**（B 侧旧版有，已迁为独立脚本，两仓同源）。

门禁 **ΔVMAF < 1.0**（VMAF 唯一判红口径）：

| 编码器 | LOO worst ΔVMAF | 主要离群素材 |
|---|---|---|
| libsvtav1 | **13.73** | new1 (13.73) / word_world_2 (4.93) |
| libaom-av1 | **6.88** | new1 (6.88) / new5_raw (3.42) |
| libx265 | **6.89** | new1 (6.89) |
| librav1e@10 | **5.05** | new1 (5.05) / new5_raw (4.24) |
| libvpx-vp9 | **4.18** | new5_raw (4.18) / new1 (3.50) |

### 3.3 根因：**模型形式不足**（不是过拟合，也不是素材池污染）

三条排除性证据（纯 CPU、零重编码，全部可复现）：

**① oracle（素材自身拟合）本身就超门禁 ⇒ 不是泛化问题。**
留出素材完全不参与拟合时，`libsvtav1` 的 ΔVMAF 仍达 **4.10（new4_raw）/ 5.61（new5_raw）/ 3.36（word_world_2）**。
即「用该素材自己拟合的直线」都达不到 1.0 —— LOO 只是把**训练内**误差暴露出来。

**② 换模型形式救不回。** 分段（2 段）把 svtav1 从 4~5.6 降到 **1.12~2.43**，仍不达标；
仿射 / 分段 / 2 点 oracle 三种形式 LOO 全部 FAIL（分段 4.2~10.7、2 点 3.8~7.7）。
二次模型看似「全 0.000 ✅」，实为**假通过**：预测参数落到扫描区间外，
`vmaf_at_param` 返回 `None` ⇒ 0 个评估点。**LOO 脚本已加断言：0 评估点判 `inf`（模型失效）而非 PASS。**

**③ 素材池污染不是主因。** 剔除 `word_world_2`（720×576 上采样，VMAF 由缩放主导）后仍全 FAIL：

| 素材集 | x265 | vp9 | aom | svtav1 | rav1e@10 |
|---|---|---|---|---|---|
| 全 4 素材 | 6.89 | 4.18 | 6.88 | 13.73 | 5.05 |
| 剔除 word_world_2 | 6.13 | 3.09 | 5.51 | 13.51 | 4.58 |
| 锚点收窄到 26/22/30/34 | 5.09 | 3.36 | 5.36 | 7.26 | 3.99 |

**归因（ΔVMAF 分解，1=全迁移 2=仅斜率迁移 3=仅截距迁移 4=oracle）**：
各素材自身的 (a, b) 分散（x265 的 a ∈ [1.031, 1.150]、b ∈ [−4.7, −0.3]），
**斜率与截距都不可迁移**（libx265/new1：仅 a 迁移 1.79、仅 b 迁移 8.90、全迁移 6.89）。
加上锚点区 x264 VMAF 局部斜率在 crf18–22 仅 −0.11~−0.49（**近乎平坦 ⇒ 参数反解条件数极差**），
小参数误差被放大成大 VMAF 误差。

> **结论**：`QUALITY_MAP` 的 `(a, b, lo, hi)` 单行仿射格式，在 4 素材 × 跨编码器口径下
> **达不到 ΔVMAF < 1.0**。达标需改为**分段/查表**形式（表格式 `(a,b,lo,hi)` 只能承载直线），
> 或按内容类型分档出表。**当前不自行放水** —— 落表决策待用户裁定。

## 4. 第一轮失败的三条根因

1. **`n_subsample=8` 偏置 VMAF**（§1.5）——跨编码器的偏置差异直接污染等 VMAF 匹配。
   这是最可能的主因，也是第二轮首要修正项。
2. **锚点 VMAF 落在目标编码器曲线的「平坦区」** —— 反查参数条件数极差。
   实测例：`new5_raw` 的 svtav1 在 crf 10→30 之间 VMAF 只从 **99.3 降到 98.6**，
   而 x264 锚点为 99.44 / 98.74 —— 落在 Plateau 上，参数几乎不可辨识。
   ⇒ 第二轮把锚点下移到 **18/22/26/30/34**。
3. **扫描两端越界，锚点覆盖不全** —— 每个编码器只用得上 5 个锚点中的 3~4 个：
   * 高端：`libaom-av1` 在 crf10 的 VMAF（98.4）仍**低于** x264 crf18（99.44），够不着；
   * 低端：`libsvtav1` 在 crf50 的 VMAF（90.2）仍**高于** x264 crf30（86.47），够不着。
   ⇒ 第二轮扫描下探到 51 / 63 / 210，锚点整体下移。

> 旁证：`libvpx-vp9` 是唯一素材间稳定、LOO 达标的编码器 —— 其 VMAF 曲线在锚点区最陡。

### 5.1 ⚠ 专用判据「5/5 达标」与 LOO「全 FAIL」不矛盾 —— 两者测的不是同一件事

## 6. 已知局限

1. **仅软编**：`h264/hevc/av1_nvenc`、QSV、AMF、VideoToolbox 需上机标定（M4）。
   `QUALITY_MAP_QP`（QP/CONSTQP 轴）的 NVENC 行为显式 `TODO(M4)`；标定前由
   `_QP_MAP_OVERRIDE` 先行命中，行为与改动前一致。
2. **素材仍偏少**：4 条，且缺**屏幕内容/文字、暗场/高噪、纯动画**三类（VMAF 最易失准的区间）。
3. **本机依赖不全**：无 torch / cv2 / numpy / pytest ⇒ `crf_cq_unification_verify.py` 的
   G4/G9/G10 组无法在本机执行（环境性 FAIL，非代码缺陷）。
4. **跨仓 rav1e speed 口径不一致**：VE 默认 **native**、VU 固定 **`-speed 10`**，却共用同一行表值。
   本报告按 speed 档**分别出表**以规避；两仓默认值是否统一仍需仓主决策。
5. **口径随 ffmpeg 构建变化**：表值仅在 §2 的二进制下可比。
6. 🔴 **表格式承载不了跨素材等质量关系（当前最大阻塞）**：`QUALITY_MAP` 的
   `(a, b, lo, hi)` 单行仿射在 4 素材 LOO 下 worst ΔVMAF 4.18~13.73（§3.2/§3.3）。
   已排除过拟合与素材池污染。要么改表格式（分段/查表），要么按内容类型分档出表，
   要么明确接受一个更宽的 ΔVMAF 门限 —— **三者都需仓主裁定，本轮不自行选择**。
   另注意：素材集仍缺**屏幕内容/文字、暗场/高噪、纯动画**三类（VMAF 最易失准的区间），
   补齐后可能进一步拉大或收窄该差距。
