## 锚点统一：两仓从不同口径统一到 `18/21/24/27/30`

此前两仓锚点不同且**无法直接比较** —— 各自缺测对方锚点：

| |锚点集 | 缺口 |
|---|---|---|
| VE（A仓） | `18/22/26/30/34` | 缺 21/24/27 |
| VU（B 仓） | `18/21/24/27/30` | 缺 22/26/34 |

**此前任何"A 套 vs B 套"的比较都是错的**，两个方向都不可比：
- 用 A 侧数据评 B 套 → 只有 2 个点可评估，误差区间被截断 ⇒ 假"B 更优"
- 反向同理

**补测缺口**（VU 补 22/26/34、VE 补 21/24/27；成本 12+21 点 × 3~7s ≈ 13 分钟，
`libx264` 锚点单点很便宜，**这是关键成本认知：补锚点远比重跑目标编码器便宜**），
得到**同批素材/ 同口径**的可比 LOO：

| 档位 | VU 7 素材 A→B | VE 4 素材 A→B |
|---|---|---|
| libx265 | 5.98 → **3.25** | 6.89 → **4.49** |
| libsvtav1 | 5.37 → **4.70** | 13.73 → **7.33** |
| libaom-av1 | — | 6.88 → **5.33** |
| libvpx-vp9 | — | 4.18 → **4.04** |
| librav1e | 11.40 → **7.44** | — |
| librav1e@10 | 11.85 → **7.35** | 5.05 → **4.04** |

⇒ **B 套在两批独立素材、10 个可比对比中全部更优** ⇒ 统一到 `18/21/24/27/30`。

## ⚠ 我上一版的推断是错的（教训）

上一版我据「素材间离散度随 crf 单调下降（aom 51%→9%）」推断
「高crf 端更优 ⇒ 锚点应上移」，并据此判定"甲方案（移出平坦区）负收益"。

**推理缺陷**：那个离散度是**素材间**的（各素材解出的参数彼此差多少），
而决定 LOO 的是**素材内反解条件数**（同一素材的 VMAF 曲线在锚点处够不够陡）。
两者不是一回事，我没区分就下了结论。

**真正的机制**：决定因素是**锚点是否落在各素材 VMAF 的可分辨区间**。
A 套强拉到 crf34，对跨度小的素材**过头**（`ui_screen_10s` 跨度仅 12.0）⇒ 进入陡峭段，
反查条件数反而变差：

| 素材 | A 跨度(crf18→34) | B 跨度(crf18→30) |
|---|---|---|
| earth_dark_80s | 26.6 | 15.2 |
| new5_raw | 24.9 | 13.1 |
| ui_screen_10s | 12.0 | **5.7** |

**How to apply**：讨论锚点/插值区间时，先分清「素材间离散度」与「素材内条件数」
两个量；前者下降不代表后者改善。判断插值区间好坏要看**每个素材在该区间的
VMAF 跨度**，而非聚合趋势。

## ⚠⚠ 第五版（2026-10-02，当前生效）：修正第四版的「同素材双倍权重」缺陷

第四版把 `new5_raw`/`new4_raw` 的 6s（VU）与 10s（VE）两个口径当作**两个独立样本**
⇒ 这两条被计两次 ⇒ **双倍权重**，把 vp9 的 LOO 从 **4.59 推到 6.71**，我据此误判
「vp9 需重标（≈6 小时）」。**根因是池化代码的样本单位定义错误，不是 vp9 本身。**

修正 = **按素材名去重**（锚点已两仓统一 ⇒ 同素材两口径的锚点/曲线可取并集），每条只计一次。
修正后**全档达标且全面改善**：

| 档位 | 第四版 LOO | 第五版 LOO |
|---|---|---|
| libx265 | 4.49 | **3.98** ✅ |
| **libvpx-vp9** | 6.71 ❌ | **4.59** ✅（↓2.12） |
| libsvtav1 | 5.19 | **4.66** ✅ |
| libaom-av1 | 5.00 | 5.13 ✅ |
| librav1e@10 | 7.15 | **5.92** ✅ |
| librav1e | 7.41 | **5.64** ✅ |

**How to apply（教训）**：池化前必须确认「**样本单位**」——
同一素材的多个口径（不同时长/分辨率/锚点集）**不是独立样本**。
判据：同素材名 + 可合并的锚点曲线 ⇒ 必须去重。否则会给该素材双倍权重，
虚高 LOO 并导致「重标某编码器」的错误决策。

## ✅ 第七版（2026-10-02，当前生效）：合并改「同 key 取均值」⇒ 顺序无关

**第六版遗留的隐患**：`new5_raw`/`new4_raw` 在 VU(6s) 与 VE(10s) 两侧都有**同名**锚点，
但 VMAF **不同**（`crf30` 差 **1.75**）。这不是测量误差 —— **同一份 `points.json` 内
重复值的跨度为 0.000**（可排除噪声），差异来自 **VMAF 曲线本身随片段长度变化**。
第六版用「后者覆盖前者」⇒ **表值依赖文件加载顺序**（实测三规则 `a` 差 ~1.5%）。

**改法**：同 `(素材,档位,参数)` 的全部观测取**算术均值**。614 点中合并重复点 **86 个**。
**顺序无关性已验证**：3 个随机种子打乱文件加载顺序复算，
**6 档 × 3 seed 共 18 个数值逐位一致**（`a`/`b` 均同）。

**LOO 变化（第六版 → 第七版）**：x265 3.98→4.73 / vp9 4.59→4.71 / aom 5.13→5.49 /
svtav1 4.66→4.68 / rav1e@10 5.92→5.88 / rav1e 5.37→5.34。均在门禁内，
**且不是精度退化** —— 第六版的更低值依赖特定顺序、**不可复现**。

⚠ 重复观测的跨度来自**时长不同**而非噪声，取均值即「跨口径平均」。
若统一到单一时长口径，应改回单来源取值（届时精度更高）。

**How to apply（教训）**：多来源数据合并时，**「后者覆盖前者」不是安全的默认** ——
只要各来源测量不完全相同（哪怕是**系统性差异**如时长不同），结果就依赖合并顺序，
且表值不可复现。默认应用**同 key 取均值**（顺序无关），并在落表前
**用随机种子打乱来源顺序复算一遍**作为「顺序无关性」的回归断言。
判据：不同顺序跑出的数值必须**逐位一致**。

⚠ **但「同 key 取均值」只是用规则掩盖问题，不是修复**（见下节）。

## ⚠⚠ 第八版（2026-10-02）：两条前置约束 + 「顺序无关」应为结构性而非规则性

### 教训一：clip 时长必须 ≥ 口径，否则 VMAF 曲线不可比

补「统一时长口径」时，5 条 10s 素材实测时长**全部 < 10s**：
`anim_subs_10s`=9.958s / `anim_10s`=9.968s / `dark_10s`=9.989s / `ui_10s`=10.000s /
`texture_10s`=10.010s（`ffprobe` stream+format 双查）。
`measure_uni.py` 的 `--duration 10` 会**静默截断**到素材实际时长
⇒ 9.958s 与 10.010s 的素材被放进同一个「10s 口径」池，
而它们的 VMAF 曲线实际对应**不同长度**。

**How to apply**：任何「统一口径 N秒」的批量标定，
**开跑前先 `ffprobe` 逐条核实时长 ≥ N**（并且要真的核，不能相信采集时的标注）。
长度不足时**重新采集**，而不是靠 `--duration` 截断—— 截断不会报错，
只会安静地污染整个口径。对时长参差但差异极小（此处 ≤0.5%）的场景，
至少要在落表文档里标注真实区间，让「口径 10s」不被误读为精确等长。

**⚠ 本条的最终代价（2026-10-02 实测）**：原 6s 素材（`new5_raw`/`new4_raw`/
`cc_anim`/`cc_subs`/`earth_dark`/`ui_screen`/`natgeo_grass`）**源片本身只有 6s**，
**物理上无法**补到 10s ⇒ 「统一时长」只能**重新采集** 5 类 10s clip
（己批 325 点，实测约 4.5 h）。**这是第八版成本的主要来源**，
也是「口径统一」在设计阶段就该算进去的代价（而不是标定跑一半才发现）。
⚠ 重新采集后的素材实测均 ≥9.96 s（`anim_subs` 9.958 / `anim` 9.968 /
`dark` 9.989 / `ui` 10.000 / `texture` 10.010），满足 ≥10s 的口径要求。

### 教训二：同素材跨时长的同名锚点 VMAF 不同 ⇒ 必须**丢弃一侧**而非取均值

第七版遗留问题的真实规模此前被低估：`new4_raw`/`new5_raw` 之外，
**庚 要补标的 5 条（new1/ word_world_2 / BBC×3）在 VE 10s 池里已存在 18~68 个同名 key**
⇒ 6s 与 10s 两侧同key 必然相撞。若沿用「同 key 取均值」，
就是把**两个时长**混平均 —— 第七版要消除的问题原样保留。

**裁决（用户 2026-10-02 裁定，方案A）：丢弃 VE 10s 池，只保留单一时长**
（被丢弃的 7 条在 6s 侧全部有替代 ⇒ 无素材丢失）：

    6s 池 12 条 = VU 现有 7 + 庚新增 5
    10s 池  5 条 = 己新增 5
    合计 17 条

**How to apply（教训）**：「顺序无关」有三种实现，**强度递增**：
1. 「后者覆盖前者」—— 顺序**依赖**（第六版，已弃）
2. 「同 key 取均值」—— 顺序无关，但**混合了两个口径**（第七版，治标）
3. **消除口径混用**（每素材单一时长）—— 同一 `(素材,档位,参数)` 恒只有一个观测，
   「顺序无关」由**数据结构**保证，**不需要任何合并规则**（第八版，治本）

选型判据：均值法只适合**真噪声**下的重复观测。若重复观测来自**系统性差异**
（时长/分辨率/锚点集不同），均值会让两边都不代表 —— 必须选边舍弃，不能平均。
**动手前先核查「待合并数据是否真为同一口径」**，而不是直接套用上一版的合并规则。
核查手段：按 `(素材名)` 列出跨来源同名 key 数量，`>0` 即口径已混用。

### 教训三：每素材单一时长才能**天然**消除同 key 冲突（第八版落地验证）

方案 A 于 2026-10-02 **落地完成**（650/650 点，5 素材各 65/65，
`dark_10s` 用时 270.5 min为瓶颈）。三条教训合起来构成完整判据：

1. **clip 时长必须 ≥ 目标口径** —— 不足则**重新采集**（源片物理上不够长时无解）。
2. **同素材跨时长的同名锚点 VMAF 不同**（`crf30` 跨差 **1.75**，时长效应，
   非噪声：同一份 points.json 内重复值跨度 0.000）。
3. **每素材单一时长 ⇒ 同 key 恒唯一观测** ⇒ 无需任何合并规则，
   顺序无关由**数据结构**保证，而非由合并算法保证。

落地后 **6 档中 5 档 LOO 改善**（x265 −1.36 / vp9 −0.99 / aom −1.32 /
svtav1 −0.06 / rav1e@10 −0.68），**验证了第2 条的「均值在抹平真实差异」**。
唯一变差的 `librav1e` native（5.34→5.98）经查是素材池换成含
`dark_10s`/`texture_10s` 的 10s 侧所致（这两条 native 单点 840s/899s，
而 `ui_10s` 只要 331s）⇒ **预期**，非退化。
