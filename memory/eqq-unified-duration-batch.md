## 用户裁定：己+庚都做（精度优先于时间）

**原话（2026-10-02）**：「选择（己+庚）：10s（补 5 类内容的 10s 数据）+ 6s（补 BBC +
new1 + word_world_2 的 6s 数据）。**时间不是问题，数据准确才有价值。**」

选项背景（我给出三选一）：戊 = 每素材单来源（零成本，但素材覆盖不变）/ 己 = 统一到
10s / 庚 = 统一到 6s。用户选**己+庚都做**⇒ 最终形态是 **17 条素材**（6s 池 12 +
10s 池 5），每条单一时长。

**Why**：零成本方案虽也全档达标，但要靠「合并规则」维持顺序无关；真正统一后
「顺序无关」由**数据结构**保证，不依赖任何规则。

##⚠ 前置硬约束：clip 时长必须 ≥ 目标口径，否则**静默截断**

| 素材 | 实测时长 | 10s 可行 |
|---|---|---|
| `cc_subs_105s`（动画+字幕） | 6.00s | ❌ |
| `earth_dark_80s`（暗场） | 6.15s | ❌ |

| `cc_anim_300s`（动画） | 8.08s | ❌ |
| `ui_screen_10s`（UI） | 10.00s | ⚠ 差 0.2s |

`measure_uni.py --duration 10` 会**静默截断到素材实际时长、不报错** ⇒ 6s 与 10s
素材混进同一个「10s 口径」池而 VMAF 曲线实际对应不同长度。

**How to apply**：批量标定开跑前**逐条 `ffprobe` 核实时长 ≥ 口径**（不信采集时的
标注）；不足则**重新采集**，不要靠 `--duration` 截断。重新采集后素材内容变了 ⇒
它们是**新增素材**而非「同一素材补另一时长」。

## 点数口径：**每素材 65 点，不是 80**

    5 锚点 + 4 软编×10 扫描 + rav1e native×10 + rav1e@10×10 = 65
    每批 5 素材 × 65 = 325 点；庚+己两批 = 650 点

⚠ 我曾把 libx264 锚点重复计入写成「80 点/素材、400 点/批」⇒ 报出的百分比全部偏低
（实际 93% 被我报成 27%）。**判断完成一律用 65 / 325 / 650。**

## ⚠⚠ 教训：监控 prompt 里的统计数字错误会伪造异常

`word_world_2` 跑满 65 点**正常退出**（日志末尾「完成：65 点」、无任何 Error 行），
但因为监控 prompt 写的是「80 点」，会被判成「进程消失且未达 80 ⇒ 异常 ⇒ 重启」⇒
**无谓重启已完成的任务**。

**正确的异常判据（必须写进任何看护 prompt）**：

    进程消失 且 键数 ≥ 预期 ⇒ ✅ 正常完成，不重启
    进程消失 且 键数 <  预期 ⇒ 重启（先确认无同 workdir 进程在跑）

**How to apply**：监控/看护脚本里的一切阈值（点数、文件数、字节数）必须
**与代码里的实际口径逐字对齐**；写错阈值比没有监控更有害——它会主动破坏已完成的工作。
改口径时**必须同步改监控 prompt**。

## 实测单点成本（2026-10-02，用于 ETA）

| 档位 | 均值 |
|---|---|
| libx264 锚点 | 3~7s |
| libx265 | 21s |
| libvpx-vp9 | 37s |
| **librav1e@10** | **67~75s**（比 native 档快得多） |
| librav1e native | 200~860s（10s 素材最慢点可达 2299s） |

**教训**：估 ETA 不要用同族最慢档的值。`librav1e@10` 与 `native` 差一个数量级，
用 native 的耗时估@10 会把ETA 夸大一倍以上。

### 残留触发时：只核实、零动作（2026-10-03 01:14/ 01:45 实测两轮）

**正确处置**＝只核实终态 + 刷新看板时间戳，**不重新测量、不重落表、不重复推送**：
核实项＝两批点数（650/650）、`ps -C python3` 无残留进程、`points.json` mtime

⚠ **本轮实测踩到的自伤式排查坑**：`pgrep -cf measure_uni.py` 与
`ps aux | grep -c '[m]easure_uni'` 都报「有进程」（2个），但那是**检查命令自身**
的命令行里含该字样而被匹配上 —— `ps -C python3` 与 `pgrep -af` 实际都为空。
⇒ 可靠判据＝**`ps -C <进程名>`**（按名字匹配，不含自身）+ 逐个读
`/proc/<pid>/cmdline` 验证。参见 [[eqq-batch-measure-parallel-constraints]]的
「pgrep 自匹配」与 [[verify-gate-concurrent-workdir-race]]。
