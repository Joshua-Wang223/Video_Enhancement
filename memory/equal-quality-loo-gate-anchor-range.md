# 等质量 LOO 门禁：判据锚点 = 生产工作区间 [0,27]

**规则**：`Accessory/probe/eqq_pool_fit_table.py` 的 LOO 判据口径由「全 5 锚点
(18/21/24/27/30) 等权 worst-case」改为 **`GATE_ANCHORS = [0,27]`**；全锚点 worst
作为**监控列**打印、**不计 FAIL**（`loo(..., anchors=CH.ANCHOR_CRFS)`）。

**Why**（2026-10-04 全 8 档实测）：现状 worst **对每个编码器都发生在最高锚点 crf30**
（8/8 满足 `≤24 < ≤27 < 全区间`）。crf30 处各编码器质量曲线进入陡降段，把小的参数偏差
放大成 5~6 dB（如 av1 的 `anim2d_forest`：全局仿射给 crf30→cq45.3，该素材真等质点 cq41.8
⇒ ΔVMAF 6.08）。这是**门禁给边界锚点同等权重**的系统偏差，不是某个编码器的换算缺陷
—— 被误当"结构性上限"。
逐锚点跨素材最差：crf18 **0.94** / crf21 **1.93** / crf24 2.91 / crf27 3.25 / crf30 **6.41**。
**仓主确认生产/CLI 的 `crf_ref` 基本不用 >27** ⇒ 判据覆盖工作区间即可，监控列保证高 ref 不隐藏。

**How to apply**：
- 跑 `eqq_pool_fit_table.py` 时看 **`LOO[0,27]`** 列判达标，`监控[全]` 仅作观察。
- ⚠ **前提若变（生产用到 ref>27）必须回头恢复全区间门禁或改稳健统计量，不得静默沿用**。
- 已排除的替代方案（均实测）：加密扫描点（6.21→6.08 仍超）、加素材（LOO 对样本量平台）、
  二次/幂模型（更差）、换 VMAF 轴（14.91 更差）、内容类截距（4.88 ✅ 但需运行期分类且每类仅 2–5 样本，仅备选）。
- 文档同步点：`Accessory/docs/EQQ_CALIBRATION_OVERVIEW.md`（表头 LOO[0,27] + 表下口径注 + 断言段）。

**先例脉络**：等质量 LOO 立项门禁原为 1.0 → 仓主放宽至 5.9（见 `equal-quality-loo-model-form-failure.md`）；
本次是把**锚点口径**也钉到工作区间（非再放宽阈值数字）。
