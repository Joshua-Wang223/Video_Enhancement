## CRF0 FORCE_CONSTQP 决策树 backport (2026-06-26)

v6.4.3.1 和 v6.4.4.1 原本使用硬编码三元表达式 `"constqp" if self.crf == 0 else _NVENC_LEVEL1_RATE_MODE`，
**没有 `_NVENC_CRF0_FORCE_CONSTQP` 开关机制**。即使用户想使用 crf=0 + VBR_HQ 也完全做不到。

从 v6.4.5.1 backport 完整决策树:
- 模块级常量: `_NVENC_CRF0_FORCE_CONSTQP` (bool, 默认 True), `_NVENC_CRF0_QUALITY` (int, 默认 0), `_NVENC_CRF0_LOOKAHEAD` (int, 默认 0)
- 两级 if/elif/else 决策块 (`CRF0-DECOUPLE`): crf=0 + FORCE_CONSTQP=True → 强制 CONSTQP; crf=0 + FORCE_CONSTQP=False → 使用配置 rate_mode + CRF0 quality 常量; crf>0 → 正常路径
- 运行时日志 (`CRF0-LOG`): 打印 crf=0 时的 rate_mode/qp/LA 决策

每文件 2 处修改: (1) 模块级常量块插入, (2) `_process_segment` 中替换 Level 1 编码器创建处的三元表达式

**Why:** v6.4.3.1/4.1 缺少 CRF0 控制开关，用户即使设置 `_NVENC_CRF0_FORCE_CONSTQP=False` 也无法使用 crf=0 + VBR_HQ/QVBR。
**How to apply:** 修改已在 v6.4.3.1/4.1 两个文件中完成，Python 语法验证通过。需 GPU 验证。
