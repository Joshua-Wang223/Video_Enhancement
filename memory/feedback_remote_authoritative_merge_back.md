**规则**：远程与本地分叉时，**以远程为权威基座**（用户原话「原则上以远程为准」）—— 对齐方式是把本地切到远程状态，**不要**用自己的版本去强推覆盖；但**本地独有的内容不是自动丢弃**，要**合并补回、再提交推送**。

**Why**：2026-09-23 用户在与本会话并行的另一个会话里，对同一远程做了「合并取长」提交（采纳我方的 FIX 成果 + 恢复 `.gitattributes` 与报告类文件 + 用 `.gitignore` 排除会话转储）。我方本地当时有 3 处远程没有的 memory 增量。用户先给出「原则上以远程为准」，随后在被问到这 3 处增量怎么办时，**明确选择「补回并提交推送」**，而不是「丢弃、完全收敛到远程」。⇒ 用户要的是"远程为基座、两边有用的东西都留下"，**不是**"本地无条件服从远程"。破坏性对齐换来的一致性，不能以静默丢内容为代价。

**How to apply**：
- 先 `git fetch`，用 `git rev-list --count HEAD..origin/main` 与 `..HEAD` 判断是**单纯落后**（可 fast-forward，绝不需要强推）还是**真分叉**；再用 `git merge-base --is-ancestor` 复核（2026-09-23 实测本地是远程祖先：落后 2、领先 0）。
- 对齐前逐条分清差异的**方向与性质**：`git diff origin/main <worktree-tree>` 的 `A`/`D` 方向极易标反（我当场标反过一次，把"本地缺"说成"将被删除"）；`M` 先用 `tr -d '\r'` 对消行尾，把「仅 CRLF/LF」与「真实内容分歧」分开 —— 32 个 `M` 里 28 个只是行尾噪音，若不分就会把噪音当冲突。
- 本地独有的东西（记忆/文档/基础设施）**别丢**：执行破坏性对齐（`reset --hard` 等）**之前**先 `cp -a` 快照到工作区外，再按用户指示合并补回并推送。⚠️ 见 [GitHub 推送流程](github-push-workflow-and-secrets.md) 里"`reset --hard` 会删掉已暂存的原未跟踪文件"这条 —— 光靠"它是 untracked 所以安全"是不够的。
- 若两侧**各有**对方没有的内容（**双向差异**），逐行合并，**不要**任一侧整文件覆盖；`MEMORY.md` 这类索引文件尤其容易双向分歧（远程更新了某行、本地新增了另一行）。
- 参照 `project_environment.md` 的「合并取长」条款；本条补充的是**用户对"以远程为准"的边界**：它约束的是**基座选择**，不授权丢本地内容。

### rebase 冲突处理 playbook（2026-09-23 实测，正是本条的典型形态）

远程被并行会话推进（`ccf2cdd..1126519`）后 `git rebase origin/main`，冲突**全在 `memory/`**
（`MEMORY.md` + `github-push-workflow-and-secrets.md`，共 3 处）。可复用的做法：

1. **合并方向**：保留 `HEAD`（远程）侧为基座，再把 `theirs` 侧**独有**行补回；同一目的的不同
   措辞取远程那版（如 GitHub 推送流程的 `[FIX-IGNORE-CANONICAL]` 新版）。
2. **去重只针对 `- [` 开头的索引条目**。第一版按"整行是否在 HEAD 里出现过"去重，结果把
   `theirs` 侧的空行与 `**How to apply**：` 这类小节标题**全吃掉**了（它们在 HEAD 侧也出现过），
   合并后的章节结构被破坏。⇒ 空行与结构化标题**永不去重**。
3. **追加 `theirs` 小节时补空行**：若其首行是 `##` 且当前输出末行非空，要先插一个空行，否则
   标题会被并进上一个列表项。
4. **长中文冲突块用 Edit 精确匹配常失败**（`String to replace not found`，字符不可见差异）；
   改用 **UTF-8 Python 脚本**解析 `<<<<<<< / ======= / >>>>>>>` 标记做定向合并。⚠️ 必须 Python
   直写文件，**不要**走 shell 管道/heredoc（中文会被控制台代码页转成字面 `?`，不可逆）。
5. 合并后 `grep -E '^(<<<<<<<|=======|>>>>>>>)'` 复核**零残留**（本会话第一版就漏掉过空行/标题，
   是靠复核+读回发现的），再 `GIT_EDITOR=true git rebase --continue`。
6. 收尾照旧：推送后独立复核 `git ls-remote origin refs/heads/main`。
