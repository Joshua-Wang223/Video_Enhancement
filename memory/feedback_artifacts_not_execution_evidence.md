判「某任务已完成 / 已落表」前，**必须有执行级、可审计的证据链**（原始 workdir / 原始采样 / 执行日志 / 会话痕迹），
不能只凭「产物存在 + 一份自述报告」。**自述报告（含 AI 会话产出的报告）是被审计对象，不是证据。**

**Why（2026-10-06，L40 AV1 专项 · av1 标定）**：
- 我把「L40 侧实质工作已完成并落表」当成结论，依据是：表值已落（`src/utils/convert_crf.py:212`
  `'av1_nvenc': (1.4566, 1.2165, 0, 63)`、`src/utils/quality_map.py:202` `(7.9338, -97.5136, 0, 255)`）
  + 池 `Accessory/data/eqq_calibration/points/gpu_l40_{cq,qp}/` + 一份自述 L40 的报告。
- 仓主直接质疑：**「`av1_nvenc` + L40/Ada 侧始终没有真正跑过标定测试，怎么能说已经完成了呢？」**
- 审计后确认执行链是断的：① 报告 `:275` 声称的 workdir `temp/eqq_gpu_l40/` **不存在**；
  ② `logs/` 只有软编素材生成日志、**无 GPU 标定日志**；③ `MANIFEST.md` 目录树**未收录** `gpu_l40_*`；
  ④ 全机 `/tmp` **无 2026-10-03~05 痕迹**（容器已重建）；⑤ 唯一存档的 L40 会话痕迹
  `/tmp/opencode/`（2026-09-30 那次）只有验证类（`av1_matrix_L40.log` / `crfcq_gpu_L40.log` / `smoke_long_*`），
  **没有 `eqq_calibrate`**；⑥ 报告自述并行会话冲突，且 CQ 行 LOO 超门禁、靠改门禁锚点才变绿。
- ⇒ 「表值已落」只能证明**有人产出过这些数**，不能证明**本项目的哪次会话在目标硬件上真的跑过**。

**How to apply**：
- 审「已完成/已落表」清单时逐项查**执行证据**：产物存在（`points/`）→ fitter 能否复现（**只证明内部自洽，不证明来源**）
  → workdir / 原始采样 / 执行日志是否存在 → 归档权威（`MANIFEST.md`）是否收录 → 会话痕迹（`/tmp`、history）是否含该命令。
  任一环缺 ⇒ 降级为「**未验证**」并列出待补证据，别写「已完成」。
- 遇用户质疑已落结论时，**先做审计、如实回报"不可审计"**，不要用「数值自洽 / 报告这么写 / 已提交」回护。
- 与 [[feedback_closure_evidence_same_scope]]（判 FAIL 闭环要同口径）互补：那条管"证据是否同口径"，
  这条管"到底有没有执行证据"。
