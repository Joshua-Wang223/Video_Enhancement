**事实（2026-10-04 实测与修复）**：`memory/MEMORY.md` 曾有 **7 条悬空链接** + **13 个 `.md` 从未被索引收录**。
修复后为 151 条、**悬空 0 / 未收录 0**（双向完整）。这不是一次性清理，索引会再次漂移。

## 双向完整性校验（可复用）

```python
import re, os
d = open('memory/MEMORY.md', encoding='utf-8').read()
links = re.findall(r'\]\(([^)]+\.md)\)', d)
missing = [l for l in links if not os.path.exists(os.path.join('memory', l))]   # 悬空
idx = set(links)
files = {f for f in os.listdir('memory') if f.endswith('.md')} - {'MEMORY.md'}
orphan = sorted(files - idx)                # 未收录
```

⚠ **`MEMORY.md` 行数超过 200 行后系统提示会截断**，所以索引必须保持**每条一行**
（标题 + 钩子），长内容放各自的 memory 文件里，索引只留一行摘要。

## 悬空链接的两类成因（都**不是**文件真的没了）

1. **相对路径基准搞错**：索引里的链接是**相对 `memory/` 目录**解析的，不是相对仓库根。
   指向 `Plan/` 下的文件必须写 `../Plan/xxx.md`，写 `Plan/xxx.md` 仍悬空（我第一版就是这么错的，
   改完仍悬空才发现基准搞错）。本轮 7 条全是这一类。
2. **文件名被记错**：索引里有一条
   `[文件缺失] la-flush-recovery-frame-conservation.md 两侧目录均不存在`，
   而实际文件叫 `la-flush-recovery-is-harmful.md` —— **文件一直在，且索引正文结论本身是对的**，
   只是文件名记错导致误判「缺失」。
   ⇒ **看到「文件缺失」标注先 `ls` 核对**，别直接信；订正时要把原正文的有价值结论保留进新条目，
   别只把删除线去掉。

## 未收录文件的 A/B/C 分档处置（不可一律塞进索引）

先派子代理分档，**再逐条自行复核**（审阅结论只是假设，见
[静态审阅结论只是假设](feedback_static_review_falsifiable.md)）：

- **A = 补索引**：内容独特、无等价条目覆盖。⚠ 尤其**零引用但规则独有的 feedback 类**
  （协作纪律不属于项目事实，不进索引就永远不会被读到）—— 本轮 11 份走这条。
- **B = 被取代**：memory/ 下另有超集文件。**不要新建重复条目**，把独有的那一条事实
  并入取代者即可（本轮 `ffmpeg9-vbrhq-removal-impact.md` 的「头文件层 vs 驱动层须分别实测」）。
  判定「是否超集」用**逐维度计数对比**（关键词在两文件的出现次数），不靠印象。
- **C = 已作废**：标 `~~` + **在文件内加失效标注**，**保留文件**而不是删。
  本轮 `pipeline-thread-coordination.md`：其结论基于已推翻的前提，但同文件另两段仍有效 ⇒
  标注失效范围即可。作废依据要**可复核**（本轮依据是「活跃包全库 grep某符号 = 0 命中」，
  而不是「我记得改了」）。
- **删除**只留给**被完全取代的纯重复项**（本轮仅 1 份：逐维度均为超集、且被取代者多出数十行），
  且须先备份 + 确认 git 可回退。

**How to apply**：新增/删除 memory 文件、或长时间批量改动之后，跑一次上面的双向校验脚本；
收尾标准是「悬空 0 / 未收录 0」，而不是「我这次加的都对」。
另：本次修复未改变其它文件的既有结论，**发现的历史遗留问题若非本轮引入，先 `git stash` 对比
HEAD 版计数确认基线，再决定是否顺手修**（避免把无关变更混进本次提交）。
